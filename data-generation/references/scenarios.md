# 场景卡

对话开始之前，先把「这次聊的是什么事」写下来。

场景不具体，对话必然空洞。这是上游关卡，卡住了后面全废。

---

# 为什么必须先写

直接生成对话，模型会自动滑向最泛的那个版本：两个人聊「工作压力」「学习方法」「人际关系」，谁也没说一件具体的事，全是车轱辘话。

场景卡强迫你先决定一件**具体发生了的事**。有了它，对话才有东西可聊。

---

# 必填字段

```
scenario   一句话说清这次聊什么，必须包含具体的人事物
domain     领域，来自 domains/_index.md
layer      话题层，A1~D6，见 SKILL.md 的配比表
opener     谁先开口，说的第一句大概是什么意思
```

选填：

```
relation   两人的关系设定，不写就用 persona 的默认
mood       user 当下的状态
history    这次对话之前发生过什么（用来测记忆一致性）
```

---

# 具体度门槛

**场景卡必须能回答这三个问题，否则不许开始写对话：**

1. 发生了一件什么事，什么时候
2. 谁受到影响，怎么受影响的
3. 有没有一个具体的东西可以聊（一个数字、一句原话、一个物件、一个时间点）

三个里缺一个，回去补。补不出来说明这张卡不成立，换一张。

## 对照

| 不合格 | 合格 |
|---|---|
| 聊聊工作压力 | 连续加班三周，今天第一次准点下班，回家发现不知道该干什么 |
| 讨论学习方法 | 考研数学做了三套卷子分数一次比一次低，最后一套只有 68 |
| 分享一个冷知识 | 刷到深海鮟鱇鱼的雄鱼会融进雌鱼身体里，觉得又浪漫又毛骨悚然 |
| 聊聊游戏 | 打了 40 小时的存档因为手滑覆盖没了，现在不想再开这个游戏 |
| 情感倾诉 | 面试第四次挂了，这次到终面，等一周收到一封模板邮件 |
| 关于宠物的对话 | 猫昨晚吐了两次，今早又活蹦乱跳，纠结要不要花三百块去医院 |

左边那列的问题不是「太短」，是**没有任何东西可以往下聊**。右边每一张都自带下一个问题。

## 具体不等于戏剧化

不需要每张卡都是人生转折。日常的小事完全可以：

```
外卖到了发现少了一份小菜，为要不要投诉纠结了十分钟
室友半夜三点还在打游戏，声音有点吵但又不好意思说
买了个二手键盘，卖家发来的实拍图和收到的手感不一样
```

小事有小事的聊法。**不要为了显得有内容而把每张卡都写成危机。**

# 一张完整的卡

```json
{
  "scenario": "面试第四次挂了，这次走到终面，聊得挺好，等了一周收到一封HR模板邮件",
  "domain": "work-study",
  "layer": "A2",
  "opener": "user 开口，情绪低但不想显得太丧，先说结果",
  "mood": "累，自我怀疑，但还没到崩溃",
  "relation": "熟，聊过几次这段找工作的事"
}
```

`relation` 里写了「聊过几次」，那对话里就应该体现出这不是第一次，比如 assistant 记得之前那几家。这是记忆一致性的来源。

---

# 一批卡不能撞车

同一个 domain 生成 N 张卡，最容易出的问题是**换汤不换药**：全是「考试没考好」的不同措辞。

三条要求：

**一、具体事物不许重复。** 同一批里不能出现两次「面试挂了」。可以有「面试挂了」和「拿到 offer 但薪资低于预期」和「入职三天想跑」，这些是不同的事。

**二、情绪不许全都一样。** 一批卡里不能全是低落。要有开心的、烦躁的、无聊的、纠结的、平静的。

**三、开口方式不许雷同。** 不能每张卡都是 user 先说、都是抛一个问题。要有：
- user 直接说一件事，不问问题
- assistant 先开口（对应 D5 主动开话题）
- user 只发一个情绪，没有内容
- 从上一次的话题接着聊

生成完一批之后自己扫一遍：把每张卡的 scenario 只留主语和动词，看看有几张是一样的。

---

# 从 domain + prompt 怎么生成

调用时会给一个 `prompt`，是这次取材的方向。比如：

```
domain: work-study
prompt: 聚焦刚工作一两年的人，不要写职场厮杀，写那些说不出口的小挫败
num: 30
```

按这个方向去想具体的事，不要跑偏到 domain 的其他角落。`prompt` 是收窄，不是扩展。

如果 `prompt` 本身很泛（「随便写点工作相关的」），先自己收窄成三四个子方向，每个方向分一部分条数，避免全部挤在最好写的那个角落。
