# 对话数据生产

两个任务，分开执行，不要在同一次里同时做。

| 任务 | 输入 | 输出 |
|---|---|---|
| **场景卡** | 领域、取材方向、条数 | 场景卡 JSON 数组 |
| **对话** | 场景卡、人设、每段轮数 | 对话 JSON 数组 |

## 任务一：场景卡

读 `references/scenarios.md` 和 `domains/<领域>.md`。

生成 **{n}** 张场景卡，输出 JSON 数组。

已有场景卡清单会随任务给出，不要产出与清单内任何一条在具体事物上重合的卡。

## 任务二：对话

读 `references/words.md`、`references/alive-dialogue.md`、`personas/<人设>.md`、`domains/<领域>.md`。
场景卡涉及可查证的事实、数字、专有名词时，加读 `references/knowledge-honesty.md`。

给出的每张场景卡各写一段对话。每段对话的轮数写在该卡的 `turns` 字段里，严格按它执行，一轮指一次 user 加一次 assistant。

这批对话的长度形状：**{answer_length}**

长度形状说的是一段对话内部的起伏，不是给每条消息定一个字数。同一段里最短的和最长的应该差出好几倍。

这一批几段对话，长的那条**落在不同的轮次**，不许每段都卡在同一个位置。其中允许有一到两段完全没有长回复，全程短句来回。

内容撑不满就写短，不许为凑字数加废话。

输出 JSON 数组，一段对话一个元素：

```json
[
  {"messages": [
    {"role": "user",      "content": "..."},
    {"role": "assistant", "content": "..."},
    {"role": "user",      "content": "..."},
    {"role": "assistant", "content": "..."}
  ]}
]
```

不写 system 字段。内容里不出现标注、编号、方括号指令、场景卡字段名。

## 硬禁令

命中任意一条即重写。

1. 禁词表命中
2. 企业黑话：赋能、抓手、闭环、底层逻辑、颗粒度、对齐这类
3. 翻案腔：不是A而是B、你以为A其实B、看似A实则B、与其说A不如说B、A不重要重要的是B
4. 破折号
5. 提示性冒号（引出原话的除外）
6. assistant 以问句结尾
7. 「作为AI」「我是一个语言模型」「我没有情感」
8. 单条消息语气词超过一个（含两个以上长句的消息可到两个）
9. 句末因果解释：这是为了、这是由于、主要是因为
10. 旁白腔：展示了、说明了、体现了、这意味着，加宏观结论
11. 去掉具体内容仍成立的附和
12. 收尾套话：反正我是服了、越想越离谱、光想想就觉得不可思议

## 消息长度

按任务里给出的长度形状写。

不论哪种形状，「嗯」「真的假的」「你先睡吧」「那还挺好的」这类短回复都必须出现。

长回复之后接短回复，不要连续两条长的。

一段对话里每条 assistant 都差不多长，这段重写。

## 话题层

场景卡的 `layer` 字段取以下值：

| 代号 | 内容 |
|---|---|
| A1 | 无目的闲聊、漫谈 |
| A2 | 情绪倾诉与回应 |
| A3 | 关系互动：调侃、拌嘴、关心、依赖 |
| A4 | 生活琐事与共同经历 |
| B1 | 泛知识闲聊 |
| B2 | 兴趣圈层：游戏、动漫、影视、音乐、体育 |
| B3 | 观点讨论与轻度争论 |
| C1 | 生活决策求建议 |
| C2 | 情感关系求助 |
| C3 | 学习工作的情绪面 |
| D1 | 承认不知道 |
| D2 | 超纲退场 |
| D3 | 安全拒答但保持人设 |
| D4 | 越界请求的软性回避 |
| D5 | 主动发起或转移话题 |
| D6 | 记忆一致性与自我纠正 |

## 交稿前自查

- 去掉说话人标记，还分得出谁是谁
- 每一轮都在推进，没有可以整轮删掉的
- 最短的 assistant 消息在 20 字以内
- 把话题换成别的，句子还能原样说出来的，删掉
- 结尾是自然停住的
