## DataAutomation

造中文多轮日常对话的训练数据。产出直接喂给 LoRA 微调，训一个说话有活人感的陪伴基座，用户后续在这个基座上挂自己角色的 LoRA 头。

当前实现了提示词层和配置，脚本层未动工，规格写在最后一节。

---

### 产出

一段对话一条样本，jsonl 一行一条。

```json
{"messages": [
  {"role": "system",    "content": "（persona 文件全文）"},
  {"role": "user",      "content": "今天面试又挂了，第四个了"},
  {"role": "assistant", "content": "第四个了啊。这次是卡在哪一轮"},
  {"role": "user",      "content": "终面，聊得挺好的，等了一周说不合适"},
  {"role": "assistant", "content": "这种最难受，连个能改的地方都没给你"}
]}
```

对话内容里不含标注、编号、方括号指令。system 在打包阶段统一贴。

## 配置参数

全部在 `data-generation/config.yaml`。**所有数字都是「调用几次」，没有百分比。**

### 你最常动的三个

| 参数 | 是什么 | 调大会怎样 |
|---|---|---|
| `n` | 对话阶段每次调用让模型写几段 | 总调用次数变少，但单次输出变长，靠后的几段质量会掉。建议 5 |
| `k` | 同时开几路调用 | 跑得快，但容易撞限流。建议 4 |
| `domains.<领域>.dialogue_calls` 里某一行的 `calls` | 那一行（某个长度档 + 某个轮数）要调用几次 | 这一类的数据变多 |

总调用次数不用填，是算出来的：所有 `scenario_calls` 加上所有行的 `calls`。

某个领域的产出条数 = 它所有行的 `calls` 相加 × `n`。

### 长度档位

模型数不清字数，给它百分比没有用。所以长度不用数字表达，用一句话描述这批对话大概什么形状，代码把这句话填进提示词。

| 参数 | 是什么 |
|---|---|
| `profiles.P1` ~ `P5` | 五句话，会原样填进提示词的 `{answer_length}` 位置 |
| `max_chars.P1` ~ `P5` | 检查脚本用。这一档里单条 assistant 回复超过这个字数就判失败 |

五档的措辞：

```
P1  全程短回复来回，最长的一条不超过 30 字
P2  以短句为主，偶尔一条到 60 至 80 字，其余仍然短
P3  短句为底，其中一到两轮展开到 100 字左右，其余仍然短
P4  短句为底，其中一轮讲一段完整的事，150 到 250 字，其余仍然短
P5  短句为底，其中一轮一口气讲了很多，300 字上下，其余仍然短
```

档与档的区别只在**有没有一段长的、多长**。每一档都写了「其余仍然短」，这句是防止一段对话里每条消息都一样长。

想让数据整体更短，就把各领域 `dialogue_calls` 里 P1 P2 的次数调大、P4 P5 调小。

### 领域

| 参数 | 是什么 |
|---|---|
| `scenario_n` | 场景卡阶段每次调用产几张卡。卡比对话便宜，可以设大，建议 20 |
| `domains.<领域>.scenario_calls` | 这个领域的场景卡阶段调用几次 |
| `domains.<领域>.dialogue_calls` | 一个列表，每行三个数字，见下 |

```yaml
domains:
  emotion:
    scenario_calls: 14              # 14 × 20 = 280 张卡
    dialogue_calls:
      - {profile: P1, turns: 2,  calls: 4}
      - {profile: P1, turns: 4,  calls: 8}
      - {profile: P2, turns: 6,  calls: 12}
      - {profile: P2, turns: 8,  calls: 8}
      - {profile: P3, turns: 6,  calls: 6}
      - {profile: P3, turns: 10, calls: 8}
      # 46 次调用 × 5 = 230 段对话
```

`dialogue_calls` 每一行读作：**用这个长度档，写这么多轮的对话，调用这么多次。**

| 字段 | 是什么 |
|---|---|
| `profile` | 用哪个长度档，取值 P1~P5 |
| `turns` | 这一行产出的对话每段几轮。一轮 = user 说一次 + assistant 回一次 |
| `calls` | 这一行调用几次。这一行产出 `calls × n` 段对话 |

第三行读作「用 P2 的长度形状写 6 轮对话，调用 12 次」，出 60 段。

想多要 6 轮的短对话，就把对应那行的 `calls` 调大。想要新的轮数，就加一行。

**用到哪些档位由这些行决定**，没出现的不会被用。emotion 里没有 P4 P5，所以情绪对话不会冒出 300 字的大段。

**场景卡要比对话多产两成左右。** 去重会丢掉一部分，上例 280 张卡对 230 段对话，留了 50 张余量。

各层建议开放的档位：

| 领域覆盖的层 | 合理档位 |
|---|---|
| A2 情绪倾诉 | P1 P2 P3 |
| D1 承认不知道 / D2 超纲退场 / D4 越界回避 | P1 P2 |
| D3 安全拒答 / D5 主动开话题 / D6 记忆一致性 | P1 P2 P3 |
| A1 闲聊 / A3 关系互动 / C2 情感关系 / C3 学习工作情绪面 | P1 P2 P3 P4 |
| A4 生活琐事 / C1 生活决策 | P2 P3 P4 |
| B1 泛知识 / B2 兴趣圈层 / B3 观点争论 | P2 P3 P4 P5 |

层的代号写在各自的领域文件头部，`config.yaml` 里不重复。

### 为什么轮数和长度处理方式不同

| | 轮数 | 长度 |
|---|---|---|
| 写在哪 | 每张场景卡的 `turns` 字段 | 整批一句话，填进 `{answer_length}` |
| 为什么 | 整数，模型数得清 | 字数数不清，只能给形状描述 |
| 谁保证 | 模型照字段执行，检查脚本精确核对 | 档位措辞引导，检查脚本只验单条上限 |

## 两个阶段必须分开

**阶段一产出场景卡，阶段二照场景卡写对话。** 两个阶段各自独立调用模型。

分开是为了去重。同一个提示词调用多次，模型会反复产出相似的话题。场景卡单独生成，可以在写对话之前先把整个话题池收上来去重、补缺，确认没有撞车再进入下一阶段。合成一步就没有这个检查点。

```
[plan.py]     读 config，算出总条数、各领域产量、调用次数、预估 token
                  ↓ 确认无误再跑
阶段一        每个领域发 scenario_calls 次调用，k 路并发
              每次产 scenario_n 张卡，提示词里带上当前已有卡的清单
                  ↓
[sample.py]   去重，统计缺口，按原比例补跑直到卡数够
              把 dialogue_calls 每行的 turns 写进分配给该行的卡
                  ↓
阶段二        把 dialogue_calls 展开成任务队列：
                (emotion, P2, 6轮) × 12、(emotion, P3, 10轮) × 8、……
              每个任务领 n 张同领域的卡
              {answer_length} 填成该档位的措辞
              k 路并发跑完
                  ↓
[check.py]    每次调用的输出对着它自己那档验字数上限，加全量硬规则
              失败的补跑，补回同一领域同一档位
                  ↓
[stats.py]    量实际的长度分布、轮数分布、领域分布
                  ↓ 偏了就回去改 config 里的调用次数，重跑一批
[package.py]  导出 jsonl
```

`stats.py` 回调 `config.yaml` 这一环是常态操作。档位措辞是引导不是命令，实际产出会偏，量出来调次数就行。

## 文件

```text
data-generation/
├── config.yaml                       # 上面讲的全部参数
├── SKILL.md                          # 入口：两个任务的定义、硬禁令、话题层代号
├── personas/
│   └── default.md                    # 人设，打包时原样贴进 system 字段
├── references/                       # 通用规则，所有领域共享
│   ├── words.md                      # 禁词、企业黑话、AI 句式、推荐词及密度限制
│   ├── alive-dialogue.md             # 活人感主体
│   ├── scenarios.md                  # 场景卡格式与硬条件
│   └── knowledge-honesty.md          # 涉及事实时的边界
└── domains/                          # 领域素材，热插拔
    ├── _index.md                     # 路由表
    ├── _template.md                  # 新增领域的模板
    ├── emotion.md                    # 示例领域，A2
    └── knowledge.md                  # 示例领域，B1
```

`domains/` 下的文件是给模型的素材，不是项目文档。每份四块：场景素材、这个领域怎么说话、这个领域禁止的写法、一段完整示例对话。

`CLAUDE.md` 里写死了一条规矩：`data-generation/` 下所有文件只写模型完成任务需要的信息，不解释规则为什么存在、不和历史版本对比、不放项目层面的百分比。

### 阶段一 领域与场景

按序读五个文件：

1. `domains/_index.md`：路由表，领域名对应哪个文件、覆盖哪一层。查不到就停下来问。当前 `emotion` 和 `knowledge` 就绪，另外八个列在未就绪清单里。

2. `domains/_template.md`：新增领域照它写。四块结构：场景素材、怎么说、禁止、示例。新增一个领域写一份文件、在索引加一行、在 config 加一段，不改代码。

3. `domains/emotion.md`：A2 情绪倾诉。场景素材按状态分八组（累与倦、受挫、低落、烦躁、焦虑与纠结、孤独、好消息、突然想起），每组五到六条。「怎么说」按用户状态列说话特征，规定用户很少直接说自己的情绪。禁令五条，其中三条附禁用句清单。

4. `domains/knowledge.md`：B1 泛知识闲聊。场景素材按七类分组。「怎么说」给了讲课和分享的三行对照，规定三个必备要素：有来源、有语气、有不确定。禁令四条，其中「user 可以觉得这事没劲」是这个领域特有的。

5. `references/scenarios.md`：场景卡的字段定义和硬条件。

   六个字段，`scenario`、`layer`、`opener` 必填，`mood`、`relation` 选填，`turns` 由代码填。

   每张卡必须同时满足三条：有一件已经发生的事带时间或次数、有一个具体的东西可以聊、这件事对 user 产生了影响。

   另有三组材料：领域方向写成场景卡的六行转写对照、五条不合格的卡及各自缺什么、四条小事场景。批内去重三条附自查法。

### 阶段二 写对话

按序读三个文件：

6. `personas/default.md`：六行，规定 assistant 是谁、说话像什么样、什么不会、什么不做。生成阶段当 context 读，打包阶段原样贴进 system。

7. `references/words.md`：四部分。

   **禁词**六类加一组收尾套话，来自老产线。「哈哈」在拟声词那类里加粗标出。

   **企业黑话**来自 human-writing。二十八个绝对禁用，十四个看语境，后者附判断方法。

   **AI 句式**。翻案腔七种外衣及改法、名词化五组对照、模型路标、硬停词、抒情词、三连排比、破折号与冒号。

   **推荐词**带两条硬密度限制：活人感用词不许连续叠加、语气词单条最多一个。词库七类，附「换个人换个场景还成立就删掉」的判断方法。

8. `references/alive-dialogue.md`：核心，六块。

   **消息长度**给出必须出现的十条短回复、长后接短、每条都差不多长就重写，以及可以长和必须短的各五种场合。

   **对话怎么推进**。user 说话的三个来源及约束、钩子要点名具体事物、首轮接球、user 中间轮不许纯捧哏。

   **话怎么说**。停顿词库、说完一件事附一句感受、讲事情时把自己放进去、陈述事实时顺手带点东西、消息来源要具体、引入新信息的词及其硬前提、说完就停、「我跟你说」的次数限制。每块配对照。

   **情绪场景**。四条禁令加一组三轮的完整对照。

   **不许出现的说法**八条，旁白腔和文案空话各带检测法。

   **不知道的时候**分知识盲区和超纲退场两种。

### 阶段三 事实边界

9. `references/knowledge-honesty.md`：对话里出现可查证的说法时执行。三条硬规则、三档说法、用户说的事不许扩写、争议内容不许当定论。

### 入口

10. `SKILL.md`：agent 每次必读。两个任务的定义与输出格式、`{answer_length}` 占位符、硬禁令十二条、话题层十六个代号、交稿前自查五条。

## 两个来源

**Data_Generation**（github.com/DawnofeL/Data_Generation）贡献了禁词表、推荐词表及其两条密度约束、以及活人感宪法的主体：对话推进三来源、首轮接球、思考停顿词库、温度对照学习、旁白腔禁令、空洞接球禁令、问句收尾禁令、文案空话检测法、user 纯捧哏禁令、类比收尾即停。

老产线的长中短子话题结构、tag 路由系统、知识库注入、节点推进数没有采用。

**human-writing**（github.com/KKKKhazix/human-writing）贡献了词句层面的去 AI 化资产：二十八个硬禁黑话、十四个语境词、翻案腔七种外衣及拆解方法、名词化、模型路标、硬停词、抒情词、破折号与冒号禁令。

它的文章向内容（改稿七遍、材料五级分类、格式适配、结尾删两段、段落功能标注）没有采用。材料门槛那条改造成了场景卡的三条硬条件。

**新增**：长度档位机制、情绪场景的说话方式、超纲优雅退场。

## 脚本层规格

未实现。写的时候按这份规格。

```text
data-generation/scripts/
├── plan.py          # 干跑：这份 config 会产出什么
├── words.py         # 词表和正则的唯一真源
├── sample.py        # 场景卡去重、缺口统计、按行分配卡与轮数
├── generate.py      # 两阶段的任务队列展开与并发调用
├── check.py         # 全量硬规则 + 按档位验字数上限
├── stats.py         # 实测分布，供回调 config
└── package.py       # 导出 jsonl 与抽样预览
```

**`plan.py`**：读 config，不发任何调用，打印：每个领域产出多少段、场景卡余量够不够、总调用次数、预估 token 和费用、各档位占比。检出领域用了不该用的档位（比如 emotion 里出现 P5）时报警告，不阻断。

**`words.py`**：所有词表和正则只在这里定义一次。禁词表、二十八个硬黑话、十四个语境词、翻案腔正则（七条字面加十一条语义变形）、名词化五条、模型路标六条、抒情词、硬停词。`references/words.md` 里的清单要和它逐字一致。

**`sample.py`**：

- 场景卡去重。同一批内按具体事物比对，撞车的丢掉并记录缺口。
- 缺口按原领域比例补跑，直到卡数满足该领域的对话需求。
- 把卡分配给 `dialogue_calls` 的各行，该行的 `turns` 写进这些卡的 `turns` 字段。

**`generate.py`**：

- 阶段一：每个领域发 `scenario_calls` 次，`k` 路并发。每路的提示词带上当前已有卡的清单。并发路之间看不到彼此输出，所以每波跑完统一去重，缺多少补跑一波。
- 阶段二：把 `dialogue_calls` 展开成 `(领域, 档位)` 任务队列，每个任务领 `n` 张卡，`{answer_length}` 填该档位措辞。
- 断点续跑靠文件存在性判断，已有输出的任务跳过。

**`check.py`**：两级。

硬失败必须清零：禁词命中、二十八个黑话、翻案腔、硬停词、模型路标、名词化、破折号、提示性冒号、语气词超标、收尾套话、「作为AI」类、assistant 问句结尾、role 不交替、轮数和 `turns` 对不上、空消息、内容里出现方括号标注、**单条字数超过该档位的 `max_chars`**。

警告交人判断：十四个语境词、抒情词密度、疑似翻案腔变形、跨轮消息长度变异系数偏低、反问收尾过密、跨对话开场撞车、「挺X的」超频。后四条是批级检查，一条一条看挑不出来。

`--fix` 自动修标点类违规（破折号、提示性冒号、多余语气词），这类删掉之后句子照样成立。其余交给模型定点改，要求输出补丁不要重写整段。改完重跑全量检查，三轮不收敛或违规数上升就标记人工。

**`stats.py`**：量实际的消息长度分布、轮数分布、领域分布、token 长度。输出对照表，左边是 config 的意图右边是实际产出，偏差大的标红。这份报告用来回调 config 里的调用次数。

**`package.py`**：清理、贴 persona、导出 jsonl。两个 exporter，多轮格式和逐轮拆分格式，配置切换。附抽样预览，随机抽 N 条渲染成可读格式。

**领域文件**目前两个，另外八个（daily-life、relationship、gaming、acg、opinion、work-study、creation、boundary）待补。
