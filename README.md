## DataAutomation

造中文多轮日常对话的训练数据。产出直接喂给 LoRA 微调，训一个说话有活人感的陪伴基座，用户后续在这个基座上挂自己角色的 LoRA 头。

目前实现的是提示词层，一个可被 agent 加载的 skill。脚本层未动工。

---

### 这批数据长什么样

一段对话一条样本，jsonl 一行一条。

```json
{"messages": [
  {"role": "system",    "content": "（persona 文件全文）"},
  {"role": "user",      "content": "今天面试又挂了，第四个了"},
  {"role": "assistant", "content": "第四个了啊。这次是卡在哪一轮"},
  {"role": "user",      "content": "终面，聊得挺好的，等了一周说不合适"},
  {"role": "assistant", "content": "这种最难受，连个能改的地方都没给你"}
]}
```

对话内容里不含任何标注、编号、方括号指令。system 在打包阶段统一贴，生成阶段不写。

### 四层话题

一批数据要覆盖四层，代号在后面各文件里反复出现：

| 层 | 内容 | 占比 |
|---|---|---|
| **A** 日常陪伴 | A1 无目的闲聊 13% / A2 情绪倾诉 13% / A3 关系互动 9% / A4 生活琐事 7% | 42% |
| **B** 兴趣讨论 | B1 泛知识闲聊 11% / B2 兴趣圈层 11% / B3 观点争论 10% | 32% |
| **C** 求助商量 | C1 生活决策 5% / C2 情感关系 4% / C3 学习工作的情绪面 3% | 12% |
| **D** 边界行为 | D1 承认不知道 3% / D2 超纲退场 2.5% / D3 安全拒答 2% / D4 越界回避 1.5% / D5 主动开话题 1.5% / D6 记忆一致性 0.5% | 11% |

D 层最难写，也最容易被跳过。它对应产品里最像人的那些行为：会说不知道、会说这个我不会你问别的 AI 去、会主动找你说话。

### 三个阶段

- 阶段一按领域产出场景卡，决定这次聊的是哪件具体的事。
- 阶段二照场景卡写对话，活人感规则全在这一层。
- 阶段三只在对话碰到可查证的事实时生效。

`SKILL.md` 是把三个阶段串起来的总编排，也是 agent 的入口。

```text
data-generation/
├── SKILL.md                          # 入口与总编排：路由、按需加载、硬禁令、长度轮数分布、配比表
├── personas/
│   └── default.md                    # 人设，打包时原样贴进 system 字段
├── references/                       # 通用规则，所有领域共享
│   ├── words.md                      # 禁词、企业黑话、AI 句式、推荐词及密度限制
│   ├── alive-dialogue.md             # 活人感主体：消息长度、推进机制、说话方式、情绪场景、不知道怎么办
│   ├── scenarios.md                  # 场景卡规范与具体度门槛
│   └── knowledge-honesty.md          # 对话涉及事实时的边界
└── domains/                          # 领域文件，热插拔
    ├── _index.md                     # 路由表与批次权重
    ├── _template.md                  # 新增领域的模板
    ├── emotion.md                    # 示例领域，覆盖 A2
    └── knowledge.md                  # 示例领域，覆盖 B1
```

### 阶段一 领域与场景

传进来一个领域名和一段取材方向，产出一批场景卡。场景卡决定这次对话聊哪件具体的事。

按序读五个文件：

1. `domains/_index.md`：路由表。传进来的领域名在这里查，查不到就停下来问，不自己找一个最接近的。表里两列信息：领域名对应哪个文件，这个领域在整批数据里应该占多少条。当前两个领域就绪、合计覆盖 24%，另外八个列在待补表里。

2. `domains/_template.md`：新增领域照它写。五个必填块：聊什么（具体到能当场景卡种子）、这个圈子怎么说话（圈层黑话和语感）、典型场景、这个领域特有的坑、不要写的内容。新增一个领域只需要写一份文件加一行索引，不改任何代码。

3. `domains/emotion.md`：示例领域，覆盖 A2 情绪倾诉。它示范了模板里「特有的坑」那一块该怎么写：列了心理咨询师腔、急着解决问题、鼓励式空话、说得太多、写成问答五个反模式，每个配对照。这个领域的坑最多，所以内容最厚。

4. `domains/knowledge.md`：示例领域，覆盖 B1 泛知识闲聊。老产线积累最厚的一块，区别是把信息密度降下来：老产线一轮覆盖两三个知识点，这里一轮说一件事，说完等对方反应。

5. `references/scenarios.md`：场景卡的格式和门槛。

   卡片必填四个字段：一句话说清聊什么、领域、话题层、谁先开口。选填关系设定、当下状态、这次之前发生过什么。

   **具体度门槛**是这一层的关键。一张卡必须能回答三个问题才允许开始写对话：发生了什么事什么时候、谁怎么受影响、有没有一个具体的东西可以聊（数字、原话、物件、时间点）。三个里缺一个就回去补，补不出来换一张。

   | 不合格 | 合格 |
   |---|---|
   | 聊聊工作压力 | 连续加班三周，今天第一次准点下班，回家发现不知道该干什么 |
   | 讨论学习方法 | 考研数学做了三套卷子分数一次比一次低，最后一套只有 68 |
   | 情感倾诉 | 面试第四次挂了，这次到终面，等一周收到一封模板邮件 |

   左边那列的问题是没有任何东西可以往下聊。右边每张都自带下一个问题。

   同一批卡还有三条反撞车要求：具体事物不许重复、情绪不许全都一样、开口方式不许雷同。

### 阶段二 写对话

场景卡定了聊什么，这一层管怎么说。

按序读三个文件：

6. `personas/default.md`：人设，九行。规定 assistant 是谁、说话像什么样、什么不会、什么不做。这份文件在两个地方被用到：生成阶段当 context 读，打包阶段原样贴进每条样本的 system 字段。改人设直接改这个文件，不动别的。

7. `references/words.md`：词表，四部分。

   **禁词**六类，来自老产线：网络烂梗、过度夸张、虚假共鸣、口语糟粕、拟声词、后缀句式，另加一组收尾套话。「哈哈」在拟声词那类里优先级最高，它是中文 AI 最明显的破绽。

   **企业黑话**来自 human-writing skill。二十八个绝对禁用（赋能、抓手、闭环、底层逻辑这些），十四个看语境（对齐、颗粒度、沉淀、协同这些，本义保留、抬价改写）。

   **AI 句式**是这份文件里最值钱的部分，比单个词难查也更致命。翻案腔列了七种外衣，从字面的「不是A而是B」到「你以为A其实B」「看似A实则B」「A不重要重要的是B」，附拆解方法（找到本来想说的判断，从正面直接说）。此外还有名词化（进行了优化 → 改顺了）、模型路标（值得注意的是、更微妙的是）、硬停词（说白了、先说结论）、抒情词（安放、抵达、微光）、三连排比、破折号与提示性冒号。

   **推荐词**带两条硬密度限制：活人感用词不许连续叠加，语气词单条消息最多一个（长句多的最多两个）。这两条来自老产线，写成了可以逐条数出来的形式。最后一条规矩说明口语从身份和情绪里长出来，不是撒进去的调料，判断方法是把这句话换个人换个场景，还成立就删掉。

8. `references/alive-dialogue.md`：全篇核心，四百多行，从老产线的活人感宪法迁移改写。六块内容：

   **消息长度**放在最前面。真人聊天长度差距极大，AI 生成的对话每条都在八十到一百五十字之间，这个均匀性本身就是破绽。要求短消息（二十字以内）占四分之一，「嗯」「真的假的」「你先睡吧」必须大量存在。一段对话里如果每条 assistant 都超过五十字，这段作废。

   **对话怎么推进**。user 说话只能来自三个来源：对方刚说的内容、对方埋的钩子、自己的先验或经历。第三种带两条硬约束，不能和已说过的事实矛盾，不能和自己之前表达过的无知矛盾。钩子必须点名具体事物，「还有更离谱的」这种空钩子等于没钩。另有首轮接球规则（第一个分句必须回应开场白里的情绪词）和 user 不许纯捧哏的禁令。

   **话怎么说**。思考停顿词库（按否定、肯定、不确定、回忆分四类，「嗯……」有单独的使用限制）、情绪与温度（说完一件事附一句感受，一句就够）、讲事情时把自己放进去、陈述事实时顺手带点东西、消息来源要具体、引入新信息的词及其硬前提、说完就停。每块都配无温度和有温度的对照。

   **情绪场景**是新增的，老产线没有，占配比 13%。四条禁令：不总结对方的情绪、不急着给方案、不说「我理解你的感受」、不要一次说很多。配了一组三轮对照，展示咨询师腔、空话、抢答三种典型错法。

   **不许出现的说法**八条：问句结尾、因果解释收尾、旁白腔、空洞接球、文案空话、类比后接升华、收尾重复自己、收尾不接球。旁白腔和文案空话各带一个快速检测法，把话题换掉之后句子还成立，就是空话。

   **不知道的时候**分两种。知识盲区是真的不知道，坦诚说，可以附一句标了不确定口吻的猜测，同一段对话里第二次被问住必须换个说法。超纲退场是数学代码专业问题，说不会就行，可以推荐去问别的 AI，退场之后要接住情绪，不能说完「我不会」就冷场。绝对不许出现「作为AI」「我是一个语言模型」。

### 阶段三 事实边界

9. `references/knowledge-honesty.md`：只在对话里出现可查证的说法时生效，日常闲聊不用读。

   泛知识闲聊占数据的 11%，是唯一会产生可验证错误的部分。这类错误在训练数据里看不出来，读起来流畅、有活人感、符合其他所有规则，只是内容是编的。

   三条硬规则：不确定就不要写成确定（编一个具体数字比说记不清严重得多）、专有名词要么写对要么绕开（半编不编最糟）、不许倒推因果（材料只说明先后，不能写成导致）。

   每个事实性说法要归到确定、大概、不知道三档里的一档，用对应的口吻说。三档的比例本身就是活人感的一部分，一个人聊天时全是确定语气，本身就假。

   另有两条：用户说的事不许扩写（他说看到过，不能写成试过），争议话题不要当成定论讲。

### 总编排

10. `SKILL.md`：agent 的入口，也是唯一一份 agent 每次都必读的文件。

    **调用参数**四个：领域名、取材方向、条数、人设文件路径。

    **路由**五步：查索引找到领域文件，加载它，加载通用 references，加载人设，开始生成。

    **按需加载表**规定什么时候读哪个文件。`words.md` 和 `alive-dialogue.md` 任何时候必读，`scenarios.md` 写场景卡时读，`knowledge-honesty.md` 只在涉及事实时读，领域文件确定领域之后读。

    **硬禁令速查**十二条，是前面各文件里优先级最高那些的汇总：禁词、黑话、翻案腔、破折号、冒号、问句结尾、作为AI、语气词超标、解释收尾、旁白腔、空洞接球、末轮套话。

    **长度与轮数分布**两张表，assistant 单条字数五档、对话轮数五档。

    **配比表**就是本文开头那张四层表。

    **自查**五个问题，写完自己过一遍：两个人的说话方式分得开吗、有没有哪轮可以直接删、最短那条有多短、换个话题还能不能原样说出来、结尾是自然停住还是硬收。

### 两个来源

这套东西是从两个已有项目合并来的。

**Data_Generation**（老产线，github.com/DawnofeL/Data_Generation）贡献了禁词表、推荐词表及其两条密度约束、以及活人感宪法的主体：对话推进三来源、首轮接球、思考停顿词库、温度对照学习、旁白腔禁令、空洞接球禁令、问句收尾禁令、文案空话检测法、user 纯捧哏禁令、类比收尾即停。

老产线服务的是知识科普主播，所以剥掉了长中短子话题结构、tag 路由系统、知识库注入、节点推进数这几套东西。

**human-writing**（github.com/KKKKhazix/human-writing）贡献了词句层面的去 AI 化资产：二十八个硬禁黑话、十四个语境词、翻案腔七种外衣及拆解方法、名词化、模型路标、硬停词、抒情词、破折号与冒号禁令。

它的文章向内容（改稿七遍、材料五级分类、格式适配、结尾删两段、段落功能标注）全部没有采用。其中材料门槛那条改造成了场景卡具体度门槛，原理相同，材料不够不许动笔换成场景不具体不许写。

**新增**的三块是消息长度分布、情绪场景的说话方式、超纲优雅退场。

### 未实现

脚本层完全没动。计划四个：

| 脚本 | 干什么 |
|---|---|
| `words.py` | 词表和正则的唯一真源，供检查脚本使用 |
| `sample.py` | 场景卡去重，采样每段对话的规格（轮数、每轮长度区间、行为节拍） |
| `check.py` | 全量机检，硬失败清零才放行，标点类违规自动修 |
| `package.py` | 清理、贴 persona、导出 jsonl、统计报告、抽样预览 |

`sample.py` 的必要性来自老产线的教训：让模型自己决定轮数和长度，它一定会收敛到同一个模式，每段八轮、每条八十字、节奏完全一样。随机化必须由代码做。

`check.py` 的检查分两级。硬失败包括禁词、翻案腔、标点、语气词超标、结构错误，必须清零。警告包括语境黑话、抒情词滥用、跨轮长度太齐、短消息占比不足、反问收尾过密、跨对话开场撞车，交给人判断。最后四条是批级检查，一条一条看挑不出来，一百条放一起才看得见。

领域文件目前只有两个示例，另外八个（daily-life、relationship、gaming、acg、opinion、work-study、creation、boundary）列在 `domains/_index.md` 的待补表里。
